# 微信公众号 Topic Intelligence｜全局选题前置规则

本规则适用于七个公众号方向：qiezhi、wechat、business、zizhitongjian、parenting、jingyun、fashion。

## 核心原则

**每天每个方向在选题之前，必须先扫描近期同类型微信公众号热门内容。**

不是先在内部题库里想题，再去找资料佐证；而是先看近期微信生态里什么主题、标题、人物、冲突和内容结构正在得到真实阅读，再形成自己的选题。

热门文章只能作为“需求信号、标题机制、内容角度、读者兴趣”输入，禁止照抄标题、结构和正文。事实仍必须回到官方、原始或高可信来源核验。

## 禁止使用 TinyFish

本 Content OS 不再依赖 TinyFish 或其他需要额外充值的钱包式浏览器服务。

默认只使用免费公开来源和普通网页搜索能力。

## 免费数据源优先级

### 1. 微信热门/榜单信号
优先抓最近 24 小时—7 天；不足时扩展到 30 天。

- 侯斯特工坊公开“微信10万+爆款文章”日榜：用于发现真实10万+标题、当天高传播结构。
- 西瓜数据公开公众号原创排行榜：用于判断同类账号近期活跃度、头条平均阅读、分类强号和相对热度。
- 其他可公开访问、无需登录/付费的微信公众号榜单、日榜、周榜。

### 2. 微信文章发现
- 普通网页搜索：查询“公众号名 + 主题 + 日期”“微信公众号 + 主题 + 最近”等。
- 搜索引擎对 mp.weixin.qq.com 的公开索引结果。
- 搜狗微信公开索引页：只有在无需验证码/登录即可读取时使用；遇到反爬/验证码立即停止，不绕过。
- 公众号文章被新闻站、机构官网、作者官网合法公开转载/引用的页面，可作为发现线索。

### 3. 非微信平台只做补充
如果微信公开索引不足，可以用小红书、微博、知乎、抖音、B站、新闻站等判断同一主题是否同时升温，但不得用它们替代“微信热门扫描”这一步。

## 每个方向的最低扫描量

每天写每个方向前，至少形成：
- 5 篇同类近期热门/高表现微信文章或榜单样本；
- 其中至少 2 条必须有可验证热度信号，例如：10万+榜单、排行榜位置、公开头条平均阅读、明确热度排名；
- 尽量覆盖 3 个以上不同公众号，避免只模仿单一账号。

若公开数据确实不足：
- 可以扩展到近30天；
- 仍不足时明确记录“微信公开热门样本不足”，再用相邻类型高热文章补足；
- 禁止编造阅读量、点赞量、公众号名或文章标题。

## 每篇选题前必须提取

对候选热门文章记录：
1. 标题；
2. 公众号/作者；
3. 发布时间；
4. 热度信号（10万+、榜单名次、头条平均阅读、公开排名等；没有则写未知）；
5. 主题；
6. 标题结构；
7. 开头钩子；
8. 核心冲突/反差；
9. 为什么可能获得点击；
10. 哪些机制可以借，哪些内容不能抄。

## 七个方向如何使用微信热门

### A 且知
微信热门只用于发现“当下人正在焦虑/讨论什么”和标题表达。思想依据固定回到《毛泽东选集》官方底本，不用公众号文章充当原典。

### B 陈慕｜AI一人公司实战
扫描 AI、Agent、独立开发、SaaS、一人公司、商业机会类热门公众号。优先捕捉真实公司事件 + 普通人可行动切口。融资、收入、用户、产品数据必须回官方/高可信来源核验。

### C 生意显微镜
扫描商业、品牌、公司故事、消费、财经类高表现文章。学习“公司名 + 冲突/转折/代价”的标题和叙事窗口；公司事实回财报/公告/监管/高可信媒体。

### D 资治通鉴
扫描历史、人性、管理、决策类热门文章，只借“今天的问题意识”和标题钩子。史实和直接引语必须回 Wikisource + CText 双底本。

### E 育儿
扫描育儿、家庭教育、青春期、学校、亲子关系类热门号。优先关注高共鸣冲突：手机、作业、上学、顶嘴、说谎、同伴、老师、青春期、父母情绪与夫妻教育分歧。不能因为某标题爆就复制恐吓、疾病化或伪专家表达。

### F 静筠日记
扫描女性、中年、婚姻、职场、钱、家庭关系类高传播文章，学习具体生活场景、现实代价、反差和情绪张力，不复制性别对立、猎奇和虚构私人经历。

### G 女装穿搭
扫描明星穿搭、日韩穿搭、女装、时尚类公众号热门文章；同时结合公开社媒/图片平台判断视觉趋势。先确认图与来源，再写普通人可复刻方法。

## 选题裁决

微信热门扫描完成后，再与本号近30天 archive 做去重。

最终候选优先级：

**近期微信热度 × 与本号定位匹配 × 新鲜角度 × 可核验性 × 可执行/可读价值 × 不撞题。**

不能因为“最近热门”就直接复制热点。真正要借的是：
- 读者此刻关心的问题；
- 标题为什么能让人点；
- 什么冲突/反差能形成阅读动力；
- 什么内容结构能让人读下去。

## 每日内部产物

每天在选题完成后，将七个方向的 Topic Intelligence 汇总为：
`content_os/topic-intelligence/YYYY-MM-DD.md`

至少包括：
- A—G 每个方向扫描到的5个样本；
- 热度证据；
- 提炼出的标题机制；
- 最终选择题目；
- 为什么选它；
- 与近30天文章如何区分。

该文件属于内部研究记录，不进入微信公众号正文。

## 发布前检查

如果当日某方向没有完成微信热门扫描：
- 不得直接进入该方向正式选题；
- 自动任务应先补扫描；
- 如果公开免费来源暂时不可用，应在最终报告中明确标记，而不是假装已完成。

## 已接入：零付费 API 的公开选题发现（2026-10-08）

- 每天 06:10（北京时间）独立运行 `content_os/free_topic_scan.py --profile all --images`，生成
  `content_os/topic-intelligence/latest.json` 和 `latest.md`，并保留按日期归档。
- 七个方向的上游写作任务在人工核验热门证据之前，应优先读取此报告，作为**候选文章索引**而非热度排行榜。
- `topic_gate=insufficient_evidence` 表示微信样本未达 5 篇或真实榜单/阅读证据不足 2 条；
  **不得将此状态包装为已完成全局热门扫描**。继续补充官方榜单等公开可核验来源。
- 图片候选来自 Wikimedia Commons，提供素材页、许可说明、作者字段，必须检查适用许可。
  明星穿搭不能用无关图库照片冒充明星真实穿搭；女装篇仍至少需要 5 张实际正文图片。
- 这是只读情报补充层；不会创建、重写或自动发布文章，也不会改动原典/图像/质量 Gate。
- Reddit、免费搜索引擎、Google News 等素材只用作发现；事实回原始可信来源复核。

## 公开第三方榜单信号的独立层级（2026-10-08）

- 每日可补充近 5 天侯斯特工坊公开的“微信10万+爆款文章”日榜，仅记录页面上可见的标题、日期、榜单名次、来源 URL。
- **榜单来源声称 10 万+，不等于官方阅读量已经核实**：不填报虚构的精确阅读数，不将榜单日期写成文章发布日期。
- 与本号方向的匹配仅由标题关键词识别，属于参考素材，不自动视为相关作者/文章已确认。
- `public_ranking_signals` 和 `heat_evidence_count` 严格分开；榜单提示不自动满足原有“5 篇样本 + 2 条已验证热度”的选题 Gate。
- 若榜单公开页面不能读取、标记日期不符或返回登录页面，记录不可用并转入现有公开来源核验流程，不绕过登录或验证码。
- 这些材料只能研究标题结构和选题热点，选题前仍须复核文章原文、账号、时间、事实与历史撞题。

## 每日写作与微信热度核验分离（2026-10-08 生效）

这两项不能再使用同一个 PASS/FAIL 判定：

- **heat_evidence_count / topic_gate**：统计可独立核验的微信文章阅读数或榜单原文证据；仅被搜狗或 RSS 搜到不算热度。第三方榜单标题若无法对应原文/发布时点，也不能写成“已验证10万+”。发现日榜几天内容几乎一样时必须标记 `suspected_repeated_snapshot`，不得当作真实连续热点。
- **writing_allowed / writing_mode**：只要当天实际尝试过公开微信索引与榜单扫描，并记录来源故障，就可以采用 `fact_verified_source_fallback` 继续原创写作；优先官方公告、原典、可靠机构和真实用户问题。不得因为 `insufficient_evidence` 跳过文章，也不能把“允许写作”误说成“热度已认证”。

扫描器运行 `python content_os/free_topic_scan.py --profile all --images`，为每个方向添加第二组免费关键词作低样本回退；去除微信公众平台登录页等伪样本，保留来源尝试、文章标题结构推断和候选来源，严格将 RSS 索引时间与微信文章发表时间分开。微信榜单不要求付费、不使用 TinyFish、不绕过验证码/登录。

## 每日两层自动验收

- 06:10 与 06:50（北京时间）由 GitHub Actions 尽力执行公开选题扫描，第二次作为免费回退；仅生成研究报告，不生成微信草稿。
- 08:20 由既有 ChatGPT 每日七公众号任务负责真正的主题核验、写稿、配图与归档；GitHub 原文/图片/质量 Gate 保持独立硬性检查。
- 10:15、13:15（北京时间）由 `.github/workflows/draft-health-audit.yml` 核查7个账号的归档 SHA、回执、今日文件、Source/Visual/Image/Quality Gate；不直接发布。发现归档已存在但未收到当日成功回执时，最多自动安全重试一次；有成功回执而文件被改动时只报警，**绝不自动重发草稿**。当天归档完全缺失时只提示上游写作任务补稿，禁止生成伪造内容。
- 报告写入 `content_os/daily-health/latest.json` 和当日归档，查询 `success_count/7`；当天文章缺失或不一致时 Actions 标红。历史 `last-failure.json` 属于故障日志，不得取代最新成功回执。
- 工作流允许多个提交排队但不主动取消正在上传微信草稿的工作；`draft_preflight.py` 对比归档与成功回执 SHA，防止普通重跑时重复入库。**微信 API 响应成功但状态写入 GitHub 前机器崩溃的极端故障，仍须人工查询草稿 ID 后恢复，不得盲目重试。**

没有任何免费公开接口可以保证七个领域每天都有5篇原始微信文章和2个真实阅读数，需如实报告证据缺口。自动化健康检查是仓库层验收，不能替代微信后台视觉与版权审查。
