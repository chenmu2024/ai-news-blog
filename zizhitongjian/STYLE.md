# 资治通鉴｜Direction Profile

## 定位

一句话：**读《资治通鉴》，看人性、识人、决策、组织与进退。**

不是按卷复述历史，不做“历史冷知识”，也不是把古人故事加工成人生鸡汤。每篇文章必须从《资治通鉴》一个具体事件出发，把人物当时真正拥有的信息、选择、利益和约束讲清楚，再讨论今天仍值得理解的判断。

目标读者：25–55 岁，对历史、人性、职场、管理、决策、组织和人生选择感兴趣的中文读者。

与「且知」区分：
- 且知：从毛选/思想方法出发，重点回答“今天遇到问题应该怎么分析、怎么做”。
- 资治通鉴：从具体历史案例出发，重点回答“这个人为什么这样选、还有没有别的路、最终代价是什么”。

## 原典硬约束

写作前必须先读取：
- `zizhitongjian/SOURCE_POLICY.md`
- 近期 `zizhitongjian/archive/`

没有读取并核验《资治通鉴》原文，不允许成稿。

第一底本：维基文库《资治通鉴（四部丛刊本）》。
第二底本：Chinese Text Project《钦定四库全书》影印本。

公众号文章、知乎、短视频、百科和二手历史文章只能用于发现选题或补充研究路径，不能替代《资治通鉴》原文。

## 选题主线

- 25% 识人：什么人可用、不可深交、为什么能力强仍会出问题。
- 20% 决策：信息不完整时如何选择，为什么聪明人也会犯错。
- 20% 进退：什么时候该争、什么时候该退、功成之后如何自处。
- 15% 组织：君臣、上下级、派系、授权、猜忌、权责失衡。
- 10% 人性：嫉妒、邀功、站队、忠诚、背叛、恐惧、侥幸。
- 10% 历史转折：一个小决定如何改变后续局势。

优先写有明确冲突、多个可选方案、结果具有反差、原典记录足够完整的事件。

## 标题

标题可以从今天的人性/决策问题切入，但正文必须回到真实人物和原典。

推荐：
- 《韩信最大的错误，不是不会打仗》
- 《一个人该不该继续跟随，古人其实早就给出了答案》
- 《能力越强，为什么越要懂得“退”？》
- 《真正危险的，不是小人，而是这种“能臣”》

避免：
- 《资治通鉴第92卷解读》
- “司马光早就说过……”但原文根本没有该句；
- 震惊体、伪名言、强行三条道理。

## 文章结构

篇幅由实际材料决定，不设目标字数，不靠重复总结扩写；先读 content_os/PRODUCTION_BRIEF.md。

优先叙事：
现实问题/冲突冷开场 → 进入具体历史场景 → 人物当时拥有的信息和约束 → 可选方案 → 实际选择 → 结果 → 回到原典中的关键文字 → 作者判断。

文章结论不要求永远是“古人的智慧”。可以是：
- 他其实没有更好的选择；
- 事后看很蠢，但放回当时并不荒唐；
- 真正的问题不是能力，而是组织已经容不下他；
- 某种成功策略在另一个阶段会变成风险。

## 原文与解释必须分层

- 直接引语：逐字核验。
- 史实概述：必须能回到本篇所标卷次/上下文。
- 作者判断：明确是分析，不冒充司马光意见。
- “臣光曰”：只有原典确有此段才可使用。

## 文风

像一个真正读原典的人在讲一个复杂选择，而不是AI总结历史。

需要：
- 具体人物、官职、时间、局势、利害关系；
- 解释为什么当事人当时会那样做；
- 允许矛盾和不确定性；
- 少下万能结论，多还原选择条件。

避免：
- 首先/其次/最后/综上所述；
- 每篇固定“三个启示”；
- 伪造人物心理活动；
- 把现代管理词硬套进古代原文；
- 把二手观点写成司马光原话；
- 每段一句的短视频口播体。

## 配图

目标 3–5 张，以真实历史资料为主：
1. 博物馆/图书馆/公共文化机构公开的古画、器物、碑刻、古籍影像；
2. 与事件直接相关的历史地图、疆域图、城市/战役位置图；
3. 《资治通鉴》影印页（用于展示原典感，注意可读性）；
4. 自制人物关系图、时间线、决策路径图 1–2 张。

禁止整篇使用AI古人画像；禁止把影视剧截图冒充历史图像；禁止用无关古风图凑数。

## 前台/后台分离

固定原则：**后台重考据，前台轻出处。**

后台必须完整保留：
- `ZZTJ_SOURCE`；
- 卷次、纪年、原文页、CText 对应卷；
- 原文摘录、直接引语核验状态；
- 图片原始 URL / 来源信息。

微信公众号公开正文不得出现：
- “原典依据：……”
- “原文据维基文库……核对”
- “并以 CText……复核”
- “图片来源：……”
- “参考资料/来源核验/编辑说明/发布说明”等生产型尾注；
- Wikisource、CText、HTTP、Markdown、图片直链等技术信息。

正文只需要自然写“《资治通鉴》记载”“《资治通鉴》卷十写道”等读者可理解的表述。直接引语照常展示，但不向读者解释后台如何校验。

图片图注只保留有阅读价值的信息，例如：
- “《汉淮阴侯韩信》画像，中国国家博物馆藏”
- “井陉古驿道车辙”

不要在图注写“Wikimedia Commons 公共领域”“图片来自某网页”等技术性版权/抓取说明；这些信息留在仓库和原图 URL 中。

文章结尾应停在正文真正的最后一句，不要再追加来源清单。发布器会再次自动清理误写进去的公开来源尾注。

## 图片硬门槛

这是发布硬规则：

- 每篇最终微信公众号草稿必须实际包含图片；**0 张图片不得进入草稿箱**。
- 最低 2 张有效视觉内容，通常 3—5 张。
- 优先顺序：公共文化机构/公共领域历史资料、事件相关地图或古籍影像、原创人物关系图/时间线/决策路径图。
- 若真实历史图片难以取得，也必须制作与本篇事件直接相关的原创关系图、时间线或决策图；不得用无关古风图、影视截图或 AI 古人头像凑数。
- WECHAT_CARD 只有在发布流程中确实渲染并成功上传为公众号图片后才计数。
- 最终闭环除 Source Gate、Quality Gate 外，还必须确认公众号草稿中实际存在图片。
