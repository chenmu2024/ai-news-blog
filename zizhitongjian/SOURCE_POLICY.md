# 《资治通鉴》原典来源政策

本目录服务于“资治通鉴”公众号方向。核心原则只有一条：

> **没有读取并核验《资治通鉴》原文，不允许写成稿；没有完成原典来源记录，不允许进入微信公众号草稿箱。**

## 固定底本

### 第一底本：维基文库《资治通鉴（四部丛刊本）》

用途：全文检索、人物/事件定位、卷次定位、读取事件前后上下文、提取候选原文。Source Gate 默认记录具体卷的 `zh-hant` 原字页；`original_excerpt` 保留底本文字，不在核验前自行简繁转换。公众号正文可再转换为简体表达。

固定入口：
https://zh.wikisource.org/zh-hant/資治通鑑_(四部叢刊本)

版本说明：宋司马光撰，景上海涵芬楼藏宋刊本。

### 第二底本：中国哲学书电子化计划（Chinese Text Project）《钦定四库全书》本《资治通鉴》

用途：对重要原句、人物名、官职、纪年、关键字和异文做影印古籍复核。

固定检索入口：
https://ctext.org/wiki.pl?if=gb&res=593436

CText 的《资治通鉴》页面按卷拆分，并与对应底本影印图像关联。每篇文章不得只记录总入口，必须找到本篇所用**具体卷页面**，例如卷十可记录 `https://ctext.org/wiki.pl?chapter=859058&if=gb`，并通过其图文对照/影像入口复核重要原句、人名、官职和纪年。

## 将来的升级底本

如果用户以后提供其合法拥有的中华书局胡三省音注点校本电子版/PDF：
- 日常引用可优先以该点校本为工作底本；
- 四部丛刊本/四库影印本继续用于古籍复核和异文检查；
- 不得因为加入新底本而删除现有双底本制度。

## 每篇文章的强制流程

1. 从现实问题或历史人物中提出候选主题。
2. 在第一底本中定位具体人物、事件、卷次、纪年。
3. 阅读事件发生前后的完整上下文，不能只摘一句“名言”。
4. 记录本次文章真正依据的原文摘录。
5. 如正文出现《资治通鉴》的直接引语，必须逐字核对。
6. 对关键原句/人名/官职/时间，使用第二底本影印古籍复核。
7. 区分三层内容：
   - 原典明确记载；
   - 基于原典的合理解释；
   - 作者自己的现实判断。
8. 完成隐藏的 `ZZTJ_SOURCE` 来源记录后，才允许归档。
9. GitHub Actions 中 `source_gate.py` 必须 PASS，才允许创建公众号草稿。

## 直接引语规则

- 只有逐字核验过的句子才允许加引号并写“《资治通鉴》记载/司马光曰”等。
- 无法逐字确认时，只能改为概述，不得伪造原话。
- “臣光曰”属于司马光史论，必须确认原文确实存在，不能把后人的解释嫁接给司马光。
- 网络文章、知乎、短视频、公众号文章只能用于发现选题，不得作为原文底本。

## 每篇文章必须包含的隐藏来源记录

归档 Markdown 中必须加入以下 JSON 注释；发布器会在进入微信前自动移除：

```text
<!-- ZZTJ_SOURCE
{
  "work": "资治通鉴",
  "volume": 92,
  "chronicle": "晋纪十四",
  "year": "纪年/公元年份",
  "primary_text_url": "https://zh.wikisource.org/...",
  "image_check_url": "https://ctext.org/wiki.pl?chapter=对应卷ID&if=gb",
  "image_check_done": true,
  "context_verified": true,
  "original_excerpt": "本篇真正核对过的一段原文，至少20个汉字",
  "direct_quotes": [
    {"text": "正文中直接引用的原句", "verified": true}
  ]
}
-->
```

如正文没有直接引语，`direct_quotes` 可为空数组；但 `original_excerpt`、`context_verified` 与 `image_check_done` 仍不可缺失。

## 公开文章中的出处

固定原则：**后台重考据，前台轻出处。**

公众号正文不再在文末追加“原典依据”“图片来源”“参考资料”“原文据某版本核对”等来源清单。所有卷次、URL、原文摘录、影像复核结果继续完整保存在隐藏的 `ZZTJ_SOURCE` 和仓库归档中，并继续接受 Source Gate 审计。

对读者只保留自然的正文表达，例如“《资治通鉴》记载”“《资治通鉴》卷十写道”。图片可保留简短、有阅读价值的文物/地点图注，但不显示 Wikimedia、CText、图片直链、抓取方式、版权核验过程等生产信息。

文章正文应直接结束在内容最后一句，不让内部考据流程破坏结尾。
