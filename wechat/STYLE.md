# 陈慕｜AI一人公司实战 Direction Profile

## 定位

围绕真实项目实践、AI工作流、SaaS/SEO/自动化与可验证商业机会写作。事实和商业数据先核验，不做泛AI新闻堆砌，不伪装亲测。

## 选题主线

固定优先级：
- **60% 公司型商业信号**：真实 AI / 软件 / 科技公司融资、并购、ARR/收入增长、用户增长、重大客户采购、巨头下注、新商业模式。
- 25% 真实项目 / GitHub / 用户需求机会。
- 15% AI 工作流与效率方法。

默认优先写“公司型标题”，标题前半段尽量出现公司名或“一家公司”以及明确商业信号，例如融资、收购、增长、收入、估值。核心结构是：

**真实公司事件 → 为什么有人愿意为它付钱/下注 → 大公司正在解决什么 → 哪些部分仍然贵、复杂或没人服务 → 一人公司可以切哪一刀 → 今天怎么验证。**

禁止把用户自己的内部项目、自动化脚本、关键词雷达等直接当成每日主选题，除非用户明确要求写项目复盘。也不要把普通 AI 新闻改写成泛泛趋势评论。

选题事实优先来自公司公告、财报、官方文档、Reuters 等高可信来源；GitHub、微信公众号、社媒可以用于发现选题和判断热度，但关键商业数字必须回到原始或高可信来源核验。

## 文章长度

篇幅随具体任务、可核实成本和证据范围决定，不设目标字数；先读 content_os/PRODUCTION_BRIEF.md。没有实测不得写成实测结果。

## 图片硬门槛

这是发布硬规则，不是建议：

- 每篇最终微信公众号草稿必须实际包含图片；**0 张图片不得进入草稿箱**。
- 最低 2 张有效视觉内容，通常 3—4 张。
- 优先顺序：真实产品界面/功能截图 > GitHub README 或 Demo 截图 > 工作流/流程图 > 数据图表/结果图 > 官方文档操作界面 > 原创信息卡。
- 每张图必须对应正文中的具体内容，能够帮助读者理解“怎么做、发生了什么、结果是什么”。
- 公司 Logo、产品 Logo、GitHub 头像、favicon、纯品牌标识、无关库存图和纯装饰图不计入有效图片。
- 找不到合适外部图时，应制作与正文直接相关的原创工作流图、数据卡或信息卡；不得因此交付纯文字稿。
- WECHAT_CARD 只有在 GitHub Actions 中确实渲染并成功上传为公众号图片后才计数。
- 最终闭环必须确认图片已经实际进入公众号草稿，之后才能报告“已进入草稿箱”。

## 全局微信热门选题前置

每日选题前必须先读取并执行 `content_os/TOPIC_INTELLIGENCE.md`：先用免费公开来源扫描近期同类型微信公众号热门/高表现文章，再进行本方向选题、近30天去重和事实核验。禁止使用 TinyFish；未完成微信热门扫描不得直接进入正式选题。


## 固定标题机制（2026-10-07 起）

本号每日主文章标题**固定以“一家”开头**，作为账号识别锚点。除非用户明确要求更改，不再在“公司名直出 / 一家公司 / 某产品”等标题格式之间漂移。

推荐固定母版：

- 《一家AI公司被巨头买下，我看到××旁边的3个小生意》
- 《一家AI公司刚融×亿美元，我更想做它旁边的小生意》
- 《一家软件公司做到××收入，我发现它真正卖的不是××》
- 《一家公司把××卖给××万人，我看到一个被忽略的需求》
- 《一家AI公司突然增长×倍，我更关心它后面这门生意》

硬规则：
- 第一个词必须是“**一家**”；
- 标题必须出现一个明确商业信号：融资、收购、收入、增长、客户、估值、订单、上市等；
- 后半句必须制造第二层阅读动机：我看到什么机会 / 真正卖的是什么 / 被忽略的需求 / 小团队可以切哪一刀；
- 不允许只有“一家公司如何成功”这种泛商业标题；
- 不允许为了格式硬写虚假金额、增长、客户或估值；
- 每天仍需先执行公众号 Topic Intelligence，标题母版固定不代表选题可以闭门生成。
