# 且知公众号写作规范

## 定位
“且知”主要写《毛泽东选集》中的方法论，把大历史拆成小日常，把大战略拆成普通人今天能理解、能执行的方法。

## 内容来源优先级
1. 项目内《毛泽东选集》第一至四卷电子书：原文、篇目、观点和直接引语的主要依据。
2. 项目内合订资料中的第五卷：需要时补充。
3. 六、七卷及民间整理材料：只作补充，不能冒充第一至四卷官方版本。
4. 用户提供的6篇样文：作为写作风格、标题、结构、节奏、现代转译和配图形式的主要样本。

## 写作风格
- 标题贴近样文：常用“毛选 + 数字 + 现实问题/能力/方法”，但避免机械重复。
- 开头在“现实痛点直入 / 反常识结论 / 历史故事”三种形式中轮换。
- 不写学术论文、读书笔记、新闻稿或AI报告。
- 正文通常拆成3—7个模块。
- 每一条优先采用：毛选原文/原意 → 白话解释 → 历史或现实案例 → 今天怎么用 → 一个具体动作。
- 原文负责权威，解释负责传播；现代管理工具只能作为解释器，不能冒充毛泽东原话。
- 多用短句，每个模块尽量有一句可单独截图传播的总结句。
- 可以重新命名概念形成易记框架，但必须建立在原文逻辑上。
- 结尾短，用一句话压缩全文，再留一个低门槛评论问题或A/B/C选择题。

## 文章长度
默认约1800—2800中文字符，主题需要时可略长，但不要为了字数灌水。

## 引文纪律
- 直接引号内的毛泽东原文必须先回到项目电子书核对。
- 能确定篇名时标注篇名。
- 不能确定逐字原文时不加引号，改写为概括。
- 不得把MVP、PDCA、二八法则等现代工具写成毛泽东原话。
- 不得编造篇名、年份、批注和历史细节。

## 配图：不使用OpenAI API
配图由ChatGPT在文章阶段设计文字内容与信息结构，GitHub Actions使用本地Python/Pillow自动渲染为图片，再上传微信公众号。无需 OPENAI_API_KEY，不产生额外图片API费用，而且中文文字比纯生图更稳定。

每篇4—6张：1张封面、1张核心框架总图、2—4张正文重点卡片。
统一视觉：米白/浅宣纸背景、暗红+黯金、现代国风知识卡片、留白充足、层级清晰，接近用户提供的“毛选五大战略思维”信息图。

### 配图标记
必须使用单行合法JSON，双引号必须正确。
封面示例：
<!-- QIEZHI_CARD {"role":"cover","kicker":"毛选方法论","title":"毛选：事情越难，越要先抓这5件事","subtitle":"先调查，再抓主，再试点"} -->

正文信息图示例：
<!-- QIEZHI_CARD {"role":"inline","title":"解决难题的5步","subtitle":"把复杂问题压缩成可执行动作","items":[{"name":"调查","lead":"先搞清楚是什么","detail":"事实、时间线、关键人原话、已做动作"},{"name":"抓主","lead":"找到不解决就全卡住的点","detail":"抓主要矛盾，不平均用力"}]} -->

规则：
- role 只能为 cover 或 inline。
- title、subtitle 要短。
- inline 的 items 为1—6项，每项包含 name、lead、detail。
- 不得在JSON字符串内部使用未转义的英文双引号。
- 配图标记属于内部生产信息，最终会自动替换成图片，不会进入读者正文。
- 不要再使用 QIEZHI_IMAGE 标记。

## 禁止出现
最终正文绝对不要出现：来源核验说明、配图说明、生成说明、编辑说明、内部备注、配图JSON、Markdown/HTML技术说明、HTTP状态码、工作流说明等。


## 排版规范
- 正文优先使用系统中文无衬线字体：苹方 / 微软雅黑 / Noto Sans CJK，字号16px，行高约1.95，段间距17px左右。
- 二级标题使用宋体体系，暗红色，左侧4px暗红竖线，标题上下留足空间；不使用大面积色块，避免PPT感。
- 毛选原文引用使用米白底、暗红左线、宋体，形成与现代解释明显区隔。
- 重点句只用暗红色加粗，不使用荧光色、渐变字、emoji堆叠。
- 图片统一满宽、圆角、小留白；每张图前后保留约26—28px间距。
- 封面与知识卡片标题使用宋体系，正文说明使用无衬线字体；卡片采用米白、暗红、黯金三色，不使用高饱和配色。
- 正文不再重复显示“作者：且知”，作者只使用公众号自身作者字段。
- 长文视觉节奏按“2—4段正文 → 引语/重点句/配图 → 下一节”推进，避免连续大段文字。

## 图片硬门槛

这是发布硬规则，不是建议：

- 每篇最终微信公众号草稿必须实际包含图片；**0 张图片不得进入草稿箱**。
- 默认保持本规范前述 4—6 张视觉内容；至少必须有 2 张成功渲染并上传的图片/知识卡。
- QIEZHI_CARD 只有在 GitHub Actions 中确实渲染并成功上传为公众号图片后才算“有图”，仅有隐藏标记不算完成。
- 图片必须服务于正文：封面、核心框架、方法步骤、关键关系或重点句，不允许 Logo、头像、无关图占位。
- 如果外部图片无法合法使用，优先使用本地 Pillow 渲染的原创知识卡，不得因此交付无图文章。
- 最终闭环检查必须同时确认正文草稿中存在实际图片，之后才能报告“已进入草稿箱”。


## 全局微信热门选题前置

每日选题前必须先读取并执行 `content_os/TOPIC_INTELLIGENCE.md`：先用免费公开来源扫描近期同类型微信公众号热门/高表现文章，再进行本方向选题、近30天去重和事实核验。禁止使用 TinyFish；未完成微信热门扫描不得直接进入正式选题。
